# Saved Results

Open **Results** in the Workbench header in the desktop app. The library is available even when the REA engine is disconnected. Select a target or choose **All saved targets**, search filenames or observed behavior, then select a file. **Description**, **Code** and **Provenance** display its explanation, bounded preview and origin.

When an analysis tool returns reconstructed source, native pseudocode, assembly, Android method source, JEB text, imported managed C#/IL reconstructions, a batch of decompiled procedures, or a published recovery output folder, Workbench retains independent copies. Each copy has an exact SHA-256 hash. Changed output bytes are retained as separate versions; repeated identical output from the same source identity is kept once. Binary resources, source maps and recovery manifests are kept alongside text files. This saves the code the tool actually returned; it does not automatically request every procedure or class in an unopened target.

Files persist through disconnect, workspace reset and app restart. Target selection changes the active session without deleting saved Results. Earlier retained tool records are imported on first opening of the library when their target identity and output bytes are still available. For older folders without retained records, select the original target and use **Import folder**. Files that a provider already removed cannot be recovered from their path alone. Symbolic links in imported trees are skipped and reported.

Each file receives a local plain-English description covering the observed file type, purpose and behavior indicators, routine declarations and inputs, returned expressions, referenced calls, dependencies and explicit unknowns. Behavioral observations include line references and the corresponding code text. These descriptions are derived from static text patterns and routine excerpts, require no API key, and never execute the target. They are not a semantic proof or an unrestricted AI account of business intent. Binary artifacts receive an explicit explanation of the unavailable text analysis. Large-file descriptions inspect the first 1 MiB; previews show at most 64 KiB, 400 lines and 4,000 characters per line. Complete saved bytes remain available in exports. Provider limitations, including reconstruction and runtime-equivalence limits, stay visible.

**Export target** or **Export all** writes a new `REA-Results-*` folder containing every file in that target scope, its `description.md` and `description.json`, a portable `manifest.json`, and a `Results.md` index. Search filters help navigation but do not silently exclude files from a target export. Exported dossiers also include the selected target's Results and explanations. Preview and export verify saved file hashes and reject modified copies.

The library lives under `results/` in the app's own analysis directory. On Linux, the default location is `~/.config/REA Workbench/analysis/results/`. Other operating systems use the REA Workbench directory under Electron's application-data directory. Installing an app update does not delete the library. There is no automatic import from another application's profile.
